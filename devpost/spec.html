ProcrastiNOT

A local-first React website whose independent deterministic scheduler proposes a realistic recovery plan, explains its choices, and waits for the student's approval.

Approved technical blueprint

How the app works

The browser shows the dashboard, local storage remembers the accepted day and read-only prior-day archives, and a separate tested function calculates proposals. Nothing is sent to an AI or a server.

The approved journey, through the code

Each step maps back to `prd.md > The Core Journey` and has a clear implementation home.

1Open the sample dashboard
`sampleDay.ts` supplies the clean baseline. `persistence.ts` loads valid browser-saved data or defaults to the sample. `App` keeps Ghost in the welcome area, shows Penguin after a newly completed task, places Hedgehog in the incomplete-task editor, and puts Jumpclip beside Add task. Cloudy remains pending until its original artwork is available; no broken image or replacement art is used.
2Edit and validate
`TaskForm` and `CommitmentForm` keep unsaved edits in the form. `validation.ts` returns field errors; valid saves dispatch one reducer action and advance the input revision. A saved edit makes a matching current proposal outdated.
3Add the 4–6 PM surprise lab
The action adds one fixed commitment (not a duplicate), leaves accepted sessions untouched, then calculates a proposal from the new revision.
4Calculate and compare
The scheduler subtracts blockers from remaining explicit study windows, orders incomplete tasks by actual deadline, priority, and original order, then uses the agreed whole-task earliest-fit rule. `RecoveryPanel` compares the result to its saved baseline and explains moved, completed, and unscheduled work.
5Approve, reject, or reset
Approval checks the input revision and current clock before any update. Rejection preserves the accepted schedule and the lab. Ordinary same-day reset restores today's sample, clears all current-day proposal history, and returns to the initial recovery preview; it does not create an archive.
6Preserve a day after date rollover
If the saved date differs from today's local date, the old plan and proposal history become read-only and editing/scheduling/approval pause. The student can cancel or confirm Start Today's Sample Day; confirmation archives the old day and activates a clean sample for today. A failed archive write leaves the old plan active.

Local-first architecture

React + TypeScript + Vite, with React's built-in reducer/hooks; no backend, account service, AI API, or extra state library.

React + TypeScriptTyped dashboard, forms, timeline, recovery comparison, and named planner actions.
Vite + CSSSimple local development/build and responsive styling with the approved warm palette.
Vitest + Testing LibraryPure scheduler tests plus a few user-visible interaction tests; development-only tools.

Run `npm install`, then `npm run dev`; open http://localhost:5173/. Verify with `npm run test -- --run` and `npm run build`. No keys or secrets are required.

Local storage is private to each browser and origin. A judge gets clean sample data; a live link is optional after the local app, public repository, licence/setup guide, and under-three-minute demo video are ready.

The scheduler in six steps

This is the agreed deterministic rule set, not an AI-generated decision.

1Keep what cannot move
Copy fixed commitments, protected sleep, unavailable periods, and completed sessions unchanged. Remove old placements only for incomplete tasks; an In progress task still needs its full entered duration.
2Calculate remaining free windows
Start from explicit study windows only. Remove every blocker. Drop fully elapsed windows and clip a window in progress to the injected current time. Empty gaps outside declared windows are never available.
3Sort tasks
Earliest actual deadline first; then High, Medium, Low; then original task order. Display categories such as Overdue and Approaching do not alter this order.
4Place whole tasks, one by one
Find the earliest slot long enough. If a whole task fits inside its preferred window, choose its earliest fit; otherwise ignore the soft preference and choose the earliest full-fit remaining slot (even if it partly overlaps that window). Subtract each placement before considering the next task. Never backtrack, split, shorten, or overbook.
5Report honestly
An unplaced task due today or earlier is At risk, with a plain reason. A future-deadline task not placed today is Not scheduled today—not described as impossible. Overdue remains an accurate deadline label even if scheduled later today.
6Protect repeatability
The engine receives current time as an input, never reads the machine clock itself. The same data and same injected time yield the same placements and explanations.

The important data boundaries

Sample baselineImmutable sample data in `sampleDay.ts`; reset always copies this clean starting point.
Accepted scheduleThe schedule currently in effect; saved separately from a generated proposal.
Proposal snapshotsInput revision, baseline, suggested sessions, explanations, and current/outdated/approved/rejected status.
Read-only day archivesComplete prior-day plan and proposal history, retained for reference and never sent to the scheduler.
Outdated protection: Saved input edits advance a revision. Approval also checks that no proposed incomplete session start time has passed. Any stale proposal stays available for review but cannot be partly applied.
PRD alignment: The approved PRD's reset remains a same-day restore of the original demo state. Confirmed date rollover is a separate behavior approved during 4-spec; the PRD has not been silently changed.
SSample data and available time
  • Protected sleep: 22:30–24:00 and 00:00–07:00.
  • Explicit study windows: 07:30–12:00, 13:00–18:00, and 18:00–22:30; no other calendar gap is assumed available.
  • Fixed lecture 09:00–10:30, fixed class 14:00–15:00, and unavailable break 12:00–13:00.
  • Completed 08:00–08:30 session stays put. Sample incomplete sessions 10:30–12:00 and 16:30–18:00; the latter visibly conflicts with the surprise lab.
  • Include a 300-minute due-today task that cannot fit as one whole session, plus a future-deadline task for truthful “Not scheduled today” behavior.

How the build will be verified

VVitest: scheduling and data rules
  • Deadline, priority, and original-order sorting; deterministic repeat runs.
  • Explicit windows with fixed/unavailable blockers; elapsed and partly elapsed windows; completed sessions in the past.
  • In progress uses full duration; exact-fit, too-short, no-time, and no-splitting cases.
  • Preferred-window selection and fallback; risk today/overdue versus not-scheduled-today future deadlines.
  • Valid clock-based approval and approval after a proposed start has elapsed; the stale case applies nothing.
  • Storage load/save, invalid saved data, same-day reset, rollover detection/archive/cancel/confirmation/write failure, no remaining windows, and same-input repeatability with a fixed test clock.
RReact Testing Library: student-visible flow
  • Dashboard starts populated; form errors preserve input and valid save updates the timeline.
  • Adding the lab creates a visible proposal but leaves accepted sessions unchanged.
  • Approval applies only a current proposal; rejection leaves the fixed lab and conflict visible.
  • Editing invalidates the proposal; same-day reset restores the initial recovery preview; date rollover pauses actions until confirmed.
  • Rollover confirmation preserves the old plan read-only and starts a clean sample for today; cancel changes nothing.
  • Reload retains saved accepted data in the same browser and invalid saved data falls back safely.
