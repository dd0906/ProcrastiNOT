ProcrastiNOT · Project guide

App map

ProcrastiNOT helps a student recover a study day when a fixed commitment disrupts it. The browser dashboard edits a sample day, calculates a deterministic schedule proposal, and lets the student decide whether to apply it. The proposal is not applied automatically.

One action, from save to feedback

When a student marks a task complete and saves it, the app validates the form, updates planner state, and shows the Penguin progress message. A regression test checks both the message and its visibility action.

How the wider app is organized

App.tsx connects the dashboard to the planner reducer. The pure scheduler in src/logic/scheduler.ts creates explainable proposals; src/storage/persistence.ts keeps the browser's saved day. There is no backend or external service.

A 3-stop route through the code

This is a reference route to follow in the editor. Search the named symbol or phrase in each real project file.

  1. src/components/TaskForm.tsx — find submit. It validates before calling onSave, so invalid values do not reach the planner.
  2. src/App.tsx — find the task editor's onSave and taskCompletionFeedback. Newly completed work sets feedback, dispatches task/saved, and renders the accessible status; the effect scrolls it into view.
  3. src/App.test.tsx — find shows the two task statuses and saves completion without rescheduling completed work. It exercises the save, checks the status and mascot asset, and verifies the scroll request.

To change this, start here

  • Change task form rules or field messages: TaskForm.tsx and its related cases in validation.test.ts.
  • Change what completion feedback says or when it appears: App.tsx; preserve the user-visible behavior in App.test.tsx.
  • Change recovery scheduling rules: start with scheduler.ts and its focused tests in scheduler.test.ts.
  • Change the dashboard's visual layout: app.css.

A practice to reuse

For a user-facing behavior, specify an observable result and verify it at the boundary a user experiences. Here, the completion feedback is not only rendered: App.test.tsx checks the accessible status, mascot asset, and scroll-to-visible request. On another project, the same approach helps catch features that exist in state or markup but are not actually noticeable to users.

Run it again

  1. From the project root, run npm install once if dependencies are not installed.
  2. Run npm run dev and open the local URL Vite reports (normally http://localhost:5173/).
  3. Run checks with npm run test -- --run and npm run build.
